# Bachelor's Thesis

**Implementation of a Simulation System for Predicting Keel-Block Reaction Forces and Optimizing Support Spacing During Ship Construction**
*Weight Distribution, Contact Algorithms, Welding Deformation and Minimax Spacing Optimisation in a Verified Python Application*

Goal: from the ship data and a detailed weight distribution (weight items with LCG or moment, or a
weight-distribution curve), compute the reaction of every keel block, and — for given block
strengths — compute the spacing of the blocks automatically so that no block carries more than its
strength, with the welding deformation of the hull as a constraint.

Bachelor of Science in Computer Science and Ship Engineering: the algorithms and the
software are the main contribution, ship engineering is the application domain.

This folder contains the thesis sources and the build script that turns them into a
submission-ready **PDF** and an editable **Word (.docx)** document.

## Output

| File | Content |
|---|---|
| `output/thesis.pdf` | Final thesis: A4, Times 12 pt, 1.5 spacing, binding margin 30 mm; Roman page numbers for the front matter and Arabic from Chapter 1; contents and lists of figures and tables with page numbers |
| `output/thesis.docx` | The same content as a Word document with native Word equations. In Word, right-click the contents and choose **Update Field** to generate page numbers. Use it when your university requires its own Word template: paste the content into that template |

## Before submission — fill in your details

1. **`metadata.yaml`**: your name, student ID, degree title, department, university, supervisor(s), place and date (title page).
2. **`front/declaration.md`**: your name and university, item 7 (use of generative AI tools, as your university's regulations require), then sign and date.
3. **`front/acknowledgements.md`**: your own acknowledgements.
4. **`references.bib`**: for the standards (MIL-STD-1625, NSTM 997, UFC 4-213-10, IACS UR S11), add the revision and year you actually consulted.
5. Check the formatting rules of your university (margins, font, citation style, word limit) and adjust the `CSS` block in `build_thesis.py` if needed.

## Building

Requirements: pandoc ≥ 3, Microsoft Edge or Google Chrome, and Python with `pyyaml` and `pypdfium2`
(`pip install -e ".[thesis]"` from the project root).

```bash
python thesis/build_thesis.py               # PDF + DOCX
python thesis/build_thesis.py --no-docx     # PDF only
python thesis/build_thesis.py --no-gui      # skip the GUI screenshots (no PyQt5 needed)
python thesis/build_thesis.py --keep-build  # keep the intermediate files in thesis/_build
python thesis/make_thesis_figures.py --regenerate        # redraw all figures
python thesis/make_thesis_figures.py --measure-scaling   # re-measure Section 5.9 (minutes)
```

The build regenerates the figures from the program, prints the main matter and the front matter
to PDF, reads the page numbers back for the contents and the lists of figures and tables, and merges
everything into `output/thesis.pdf`. Appendix B is regenerated from the current source code on
every build; the intermediate folder `_build` is deleted afterwards unless `--keep-build` is given.

## Writing conventions

- Numbered headings are written explicitly (`# 3 Methodology`, `## 3.1 …`).
- Display equations: `$$ … \tag{3.1} $$`. The build converts the tag into a right-aligned number.
- Figures: `![Figure 3.1: Caption.](figures/file.png)`. Tables: a pipe table followed by
  `Table: Table 3.1 – Caption.` Both are collected into the lists automatically.
- Citations: `[@key]` with keys from `references.bib` (author–date style via pandoc citeproc).

All results for the example vessel come from the program in this repository. The example data are
illustrative placeholders, not data of a real ship; the thesis states this wherever they are used.
